# 插件系统

流程插件用于在漫画翻译步骤中添加自己的处理逻辑，例如清洗 OCR 文本、统一译文或修正样式。不想手写代码时，也可使用内置 Plugin Agent 辅助生成。

::: tip 与浏览器插件的区别
本页介绍 Python 流程插件。要在漫画网页上直接翻译图片，请查看[浏览器插件](/use/browser-extension)。
:::

## 入口位置

1. 进入翻译页面。
2. 点击顶部**设置**。
3. 切换到**插件管理**。

本功能用于本地版本；公共部署可能不提供流程插件能力。

## 导入与启用

当前插件使用 v3 ZIP 包。导入后在列表检查名称、版本和状态，再启用。

| 操作 | 作用 |
|------|------|
| 运行时启用 / 禁用 | 控制本次后端运行期间新任务是否使用插件 |
| 默认启用 | 控制下次后端启动时的初始状态 |
| 配置 | 编辑插件提供的参数 |
| 刷新 | 重新校验受管理插件状态，不从任意目录热加载代码 |
| 导入 / 导出 | 安装新包，或导出可分享的插件包 |
| 删除 | 删除允许移除的版本；被任务或操作历史引用时会拒绝删除 |

::: warning 旧插件
旧版继承 PluginBase、只包含 Python 文件的目录不能直接当作 v3 包使用。开发与改造方法见[插件开发总览](/advanced/plugin-development-overview)。
:::

## 何时生效

后端创建任务时，会固定当前启用插件的版本与配置。

- 开关和配置变更影响后续新建任务。
- 已入队任务及其暂停恢复继续使用原版本。
- 重试会创建新任务：选择“沿用原快照”保留原插件版本；支持“按当前设置重试”的任务会重新获取当前启用插件与配置。
- 更新插件需重新导入 ZIP；不要直接修改已发布目录。

这能保证同一个任务在暂停恢复后继续使用相同代码。

## 插件可以做什么

- 在 OCR 后整理文字。
- 在普通翻译或 AI 翻译后修正结果。
- 在修复和渲染前后处理数据。
- 在任务生命周期中记录或校验信息。

不同模式经过的步骤不同。普通翻译后处理不一定会在高质量翻译中运行，应查看插件声明的支持模式。

## 自动生成插件

在插件管理中打开自动生成入口，配置模型、描述需求并确认方案。执行期间可在任务中心查看，生成后先用少量图片验证。

详细说明见[自动生成插件开发](/advanced/plugin-agent-development)。

## 出现问题时

先检查插件状态和任务错误。如果普通后处理插件采用继续策略，失败时会记录警告并保留原数据；采用失败策略的插件则会让相应任务或任务项失败。

启用前后对比时，应分别创建任务，避免旧任务的配置快照影响判断。
