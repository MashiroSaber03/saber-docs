# 漫画续写

漫画续写是 Saber Translator 在漫画分析体系上延伸出来的一项创作型功能。它不是简单地“直接生图”，而是先基于已有的分析结果理解原作剧情，再按工作流逐步生成续写脚本、页面剧情和最终图片，从而尽量保证故事与画风的连续性。

## 功能概述

漫画续写主要包含四个步骤：

1. **角色设置**
2. **生成脚本**
3. **页面剧情**
4. **图片生成 / 导出**

在这个流程中，系统会尽量复用已完成的漫画分析结果，帮助您从“理解原作”过渡到“继续创作”。

::: tip 适合什么场景
- 想为现有漫画制作原创后续剧情
- 想基于原作角色继续扩展支线故事
- 希望先有脚本和页面剧情，再逐步控制最终生图结果
:::

---

## 前置条件

在使用漫画续写之前，建议先完成以下准备：

1. 目标书籍已添加到[书架系统](/use/bookshelf)
2. 章节图片已经上传完成
3. 已完成基础的[漫画分析](/use/manga-insight)
4. 在分析设置中已经配置可用的生图模型与分析模型

如果分析数据还不完整，续写页面通常会先提示您同步或补齐分析结果。

---

## 入口位置

漫画续写位于**漫画分析**页面内部。

进入方式：

1. 从[书架系统](/use/bookshelf)进入目标书籍的分析页
2. 进入[漫画分析](/use/manga-insight)
3. 切换到**漫画续写**相关标签
4. 按四步工作流逐步完成续写

漫画续写并不是独立于分析之外的孤立功能，它更像是“建立在分析结果之上的继续创作”。

---

## 第一步：角色设置

角色设置是续写流程的起点。在这一步中，您需要决定续写中会用到哪些角色，以及这些角色的基本参考信息是否齐全。

### 可配置内容

- **续写页数**：决定本次准备续写多少页
- **画风参考页数**：决定生图时参考多少张原作或已有图片
- **续写方向**：用自然语言描述您希望故事往哪里发展
- **角色管理**：检查当前续写中要使用的角色与角色形态

### 这一阶段的作用

- 先把“故事要往哪走”定下来
- 确定会出场的人物范围
- 为后续脚本生成和生图提供基础约束

::: tip 提示
如果您暂时没有非常明确的剧情方向，可以先给一个简短的续写意图，例如“延续主线”“加入新的冲突”“侧重角色日常”。先让流程跑起来，再在后续步骤继续细化。
:::

---

## 第二步：生成脚本

脚本生成是续写流程中最关键的一步之一。系统会结合已有分析结果、您提供的续写方向以及参考图信息，先生成整话级别的续写脚本。

### 基本流程

1. 设置续写方向和页数
2. 选择默认参考图或自定义参考图
3. 点击生成脚本
4. 查看系统生成的整话脚本
5. 按需手动修改并保存

### 脚本阶段的特点

- 更偏向“整话规划”
- 用来决定每一页大致发生什么
- 不是最终成图提示词，而是后续页面剧情的基础

如果您对脚本不满意，建议优先在这一阶段重写或微调，而不是直接跳到后面的图片生成阶段再返工。

---

## 第三步：页面剧情

在整话脚本确定后，系统会继续把脚本拆分为逐页剧情内容。每一页都会生成对应的剧情描述、关键对白、出场角色以及用于后续生图的核心内容。

### 这一阶段通常包含

- 当前页剧情承接
- 本页主要事件
- 关键对白
- 出场角色
- 页面级的最终提示词基础

### 使用建议

1. 先批量生成页面剧情
2. 逐页检查逻辑是否连贯
3. 如果发现某一页偏离预期，优先直接修改该页剧情
4. 保存后再进入生图阶段

::: warning 注意
如果您在脚本阶段做了较大修改，建议重新检查页面剧情，而不是直接沿用旧结果。
:::

---

## 第四步：图片生成与导出

在页面剧情确定后，就可以开始为每一页生成续写图片了。

### 图片生成阶段会做什么

- 读取当前页剧情与对白信息
- 结合角色信息和角色形态
- 使用参考图维持画风一致性
- 生成对应页的最终图片
- 支持单页重生或批量生成

### 常见操作

| 操作 | 说明 |
|------|------|
| **批量生成** | 按当前页序整体生成多页图片 |
| **单页重生** | 对某一页单独重新生成 |
| **继续沿用上一版** | 在多次尝试中保留更满意的结果 |
| **导出** | 导出为图片集合或 PDF 等形式 |

### 参考图的作用

续写生图通常会参考两类内容：

- **原作图片**：帮助保持画风和角色表现稳定
- **已生成续写图片**：帮助续写页面之间保持连续性

因此，画风参考页数并不是越大越好。一般建议先从少量参考开始，确认风格稳定后再调整。

## 推荐使用流程

比较稳妥的续写流程通常是：

1. 先完成[漫画分析](/use/manga-insight)
2. 在角色设置中明确续写方向和页数
3. 先生成整话脚本并人工检查
4. 再生成页面剧情并逐页修正
5. 最后进入图片生成阶段
6. 对不满意的页面单独重生
7. 全部确认后再导出

这样的好处是，问题会尽量在前面的文字阶段被发现，而不会等到已经生成完图片才集中返工。

---

## 常见使用建议

### 想提高续写连贯性

- 先确保漫画分析结果本身是完整的
- 续写方向不要写得过于模糊
- 先把脚本阶段打磨清楚
- 不要跳过页面剧情检查

### 想提高画风稳定性

- 使用合适数量的画风参考页
- 尽量保证参考图本身质量稳定
- 对关键角色先整理好角色信息和形态
- 对问题页优先单独重生，而不是整批推翻

### 想减少返工

- 先少量页数试跑
- 确认整体风格可接受后再扩大规模
- 重要修改尽量前置到脚本或页面剧情阶段

## 常见问题

### 为什么续写前要先做漫画分析？

因为续写依赖已有分析结果来理解原作剧情、人物关系和故事走向。没有这些基础信息，系统很难稳定地继续创作。

### 我可以只生成脚本，不立刻生图吗？

可以。实际上这也是比较推荐的方式。先把脚本和页面剧情整理好，再开始生成图片，整体可控性会更高。

### 续写方向一定要写得很详细吗？

不一定。您可以先给一个大方向，让系统先生成初稿；如果结果不够理想，再逐步细化。

### 生成出的某一页不满意怎么办？

优先检查该页的页面剧情和提示词是否需要调整；如果文字层没问题，再使用单页重生继续尝试。
