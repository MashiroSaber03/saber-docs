# 自动生成插件开发

内置 Plugin Agent 可以根据自然语言创建或修改流程插件。它按当前 Plugin v3 契约工作，适合明确、范围较小的处理需求。

## 工作流程

1. 在**设置 → 插件管理**打开自动生成插件。
2. 配置插件 Agent 使用的模型服务。
3. 选择新建或修改，描述需求并确认方案。
4. 执行阶段创建后台任务，由 Worker 编写和校验。
5. 成功后发布新插件版本，在列表中检查、启用并用新任务测试。

规划会话有有效期，不应当作长期项目存档。真正的编程执行是持久任务，浏览器断线不会终止执行，取消和查看进度可通过[任务中心](/use/task-center)。

## 如何描述需求

把步骤、模式、规则和预期效果说清楚：

- “创建 `after_translate` 插件，只在 `standard` 模式下清理 `translations` 首尾空格。”
- “创建 `after_ocr` 插件，修正常见 OCR 错字，并保持原文与 OCR 结果一致。”
- “修改现有插件，保留现有功能，只新增一项可配置的后缀。”

不必一次提出复杂系统；先验证一个可见的小效果更容易定位问题。

## 生成后检查什么

| 检查项 | 要求 |
|--------|------|
| 清单 | `schema_version: 3`，入口、Hook、步骤和模式对应 |
| 类和方法 | 无参入口类，同步实例 Hook |
| 返回值 | 返回完整、符合契约的 JSON 对象，不能是 None |
| 字段 | 使用 `translations`、`originalTexts` 等当前字段 |
| 测试方式 | 启用后创建新任务，不拿旧任务验证新版本 |

详细说明见[Hook 与数据契约](/advanced/hook-contract)。

## 版本与文件

Worker 在任务的临时工作目录中操作文件，通过校验后发布受管理的新版本。不要到 `data-v2/plugins` 中直接修改已发布代码。

修改代码、导入新版本或改变配置都不会替换已入队任务使用的插件快照。需要验证新版本时，重新发起翻译。

## 何时改为手写

需要精细控制算法、多个步骤协同或复杂数据处理时，可将生成结果导出后自行修改，再重新打包导入。无论手写还是 Agent 生成，都使用同一份 v3 契约。

入门可参考[第一个插件](/advanced/first-plugin)。
